# 用户偏好

## 语言
- **回复语言**：中文（默认）
- **代码注释/文档**：中英文混合（技术术语用英文，说明用中文）
- **提交信息**：英文（GitHub 标准）

## 技术风格
- **深度优先**：关注底层设计和架构决策，不满足于表面实现
- **哲学驱动**：喜欢从 OS 哲学、系统思维角度思考问题
- **拒绝浅层**：对"很多都在做了"的平庸方案不感兴趣（如 Agent 系统指令不可篡改）

## 工作模式
- **快速执行**：选择方案后希望立即实施，不拖泥带水
- **并行推进**：可以同时推进多个独立任务（如主权系统 + 验证代理）
- **性能敏感**：明确要求"注意性能"，关注 O(1)、热路径优化
- **质量导向**：接受多轮 review-fix 循环，不急于合并

## 关注点
- **OS 隐喻的深度应用**：不只是框架层面的进程调度，而是 Agent 内部的微内核
- **Agent 主权**：真正的自主决策权，不是模拟的权限系统
- **开源潜力**：思考项目是否能成为有价值的开源贡献
- **学习价值**：希望项目能促进自己的学习和成长
- **Chora 哲学**：场域（χώρα）而非容器——Runtime 使协作成为可能，但不规定协作形式

## 设计哲学（2026-06-28 明确）
- ✅ 场域：提供基础设施（IPC、AFS、协商协议），让协作自然发生
- ❌ 容器：给 Agent 加外壳、限制行为、强制结构
- ✅ 抽象映射：从 OS 哲学提取原则（隔离、控制、共享），不复制具体组件
- ❌ 硬件抽象：不引入设备驱动、内存分区等 OS 组件
- ✅ 多主体共生：场域容纳多个主权 Agent，形式从协商中涌现
- ❌ 单 Agent 优化：聚焦多 Agent 协作，不是单个 Agent 的功能堆砌

## 决策风格
- **组合选项**：经常选择多个选项的组合（如 BC、AC）
- **追问细节**：希望我主动提出需要澄清的问题
- **不满足于现状**：总是问"下一步是什么"，追求持续演进

## 项目命名偏好
- **Chora**：希腊哲学中的"原始场域/容器"（χώρα），先于形式、容纳形式
- **Frostsnow35**：GitHub 用户名，可能反映个人审美偏好
