# 研究方向的开放问题

## 🔴 高优先级（影响项目定位）

### Q1: 项目的核心定位是什么？
**现状**：Chora 目前是研究性开源项目，使用 MockAgent 验证，未接入真实 LLM。

**问题**：
- Chora 的最终目标是什么？
  - A) 理论研究框架（专注于设计哲学和架构创新，验证代理用 Mock 即可）
  - B) 生产级运行时（需要接入真实 LLM，考虑性能、成本、可靠性）
  - C) 教学工具（专注于清晰的设计模式，让他人学习 OS 启发的 Agent 设计）
  - D) 混合（阶段性目标，先理论研究，后生产化）

**影响**：决定了后续是否需要实现真实 LLM 集成、性能优化、错误处理、监控等。

### Q2: "天马行空的想法"具体是什么？
**现状**：用户提到有"天马行空的想法"，但未具体说明。

**问题**：
- 你内心最想让 Chora 实现的独特能力或特性是什么？
  - Agent 的某种特殊能力？（如跨 Agent 学习、自我修改代码、情感建模）
  - 某种架构创新？（如 Agent 网络拓扑、动态主权协商、意图继承）
  - 某种应用场景？（如多 Agent 协作写作、自主科研、代码审查网络）

**影响**：决定了 RFC-004+ 的设计方向，以及是否需要在当前架构上做重大扩展。

### Q3: 主权系统与真实 LLM 的关系？
**现状**：当前 TrustMeter 基于行为记录更新分数，但 LLM 的实际推理过程是黑盒。

**问题**：
- Trust Score 如何影响 LLM 的实际行为？
  - A) 仅作为能力门控（Level 不够时禁用某些工具/API）
  - B) 注入到 prompt 中（如"你的自主权级别是 2，可以..."）
  - C) 影响推理参数（如调整 temperature、top_p）
  - D) 完全独立（Trust Score 只是运行时状态，不影响 LLM 推理）

**影响**：决定了主权系统是"真主权"还是"伪主权"，以及是否需要修改 LLM 调用逻辑。

## 🟡 中优先级（影响实施路径）

### Q4: RFC-002 调度系统的优先级？
**现状**：RFC-002 设计已完成，但未实施。

**问题**：
- 调度系统的实施优先级如何？
  - A) 立即实施（完善核心运行时，为多 Agent 场景做准备）
  - B) 暂缓（当前单 Agent 场景已足够，先探索其他方向）
  - C) 简化实施（只实现 FIFO + Token Budget，不做复杂策略）

**影响**：决定了下一个 sprint 的工作重点。

### Q5: 目标社区和受众？
**现状**：GitHub 仓库已创建，但未推广。

**问题**：
- Chora 的目标受众是谁？
  - A) Rust 社区（强调 Rust 的并发安全性和性能）
  - B) AI 安全社区（强调 Agent 主权、能力系统、可解释性）
  - C) ML 研究者（强调架构创新和实验可复现性）
  - D) 通用软件开发者（强调清晰的设计模式和易用性）

**影响**：决定了文档风格、示例复杂度、推广策略。

## 🟢 低优先级（锦上添花）

### Q6: 内存层的持久化策略？
**现状**：MemoryTool 使用 in-process HashMap，进程重启后丢失。

**问题**：
- 是否需要持久化内存？
  - A) 不需要（研究项目，in-process 足够）
  - B) 需要（生产化必备，考虑 SQLite、Redis、文件存储）
  - C) 可选（提供 trait，用户自行实现）

### Q7: 多 Agent 拓扑的探索方向？
**现状**：当前支持 Agent 间通信，但拓扑结构未深入探索。

**问题**：
- 是否想探索特殊的 Agent 网络拓扑？
  - A) 层级结构（Supervisor → Worker 树）
  - B) 对等网络（Agent 间直接协商）
  - C) 动态拓扑（Agent 可动态加入/离开网络）
  - D) 暂不探索（先完善单 Agent 能力）

## 📋 建议的决策顺序
1. **Q1（项目定位）** → 决定整体方向
2. **Q2（天马行空的想法）** → 决定创新点
3. **Q3（LLM 集成方式）** → 决定主权系统的真实性
4. **Q4（调度系统优先级）** → 决定短期实施计划
5. **Q5（目标受众）** → 决定文档和推广策略
6. **Q6/Q7** → 锦上添花
