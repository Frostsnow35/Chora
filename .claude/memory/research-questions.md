# 研究方向的开放问题

## 🔴 高优先级（已决策）

### Q1: 项目的核心定位是什么？
**决策（2026-06-27）：AB 组合**
- ✅ 专注于理论研究（OS启发的架构创新，验证代理为核心）
- ✅ 但也要接入真实LLM来展现能力（Demo + 实验）

**影响**：
- 核心架构保持研究导向，不追求生产级可靠性
- 需要设计真实LLM集成层（作为可选feature，非核心）
- 验证代理可以继续用MockAgent
- 新增实验性验证代理展示真实LLM行为

### Q2: "天马行空的想法"具体是什么？
**决策（2026-06-27）：OS底层创新（开放式探索）**
- ✅ 与OS有关的创新，保持开放探索
- ❌ 不追求硬件级别的隔离（软件层面不现实）
- ✅ 多种OS-inspired机制都可以考虑：
  - Agent间的IPC创新（管道、消息队列、信号量、共享内存等）
  - Agent的"文件系统"（知识持久化和共享）
  - Agent的"设备驱动"（统一抽象工具/能力）
  - Agent的"中断机制"（响应外部事件）
- ✅ 未来研究逐步尝试，不急于定义单一RFC-004

**实施策略**：
- 保持架构的可扩展性，为未来OS-inspired创新留空间
- 可以有一系列探索性RFC（RFC-004, RFC-005, ...）
- 每个RFC聚焦一个OS-inspired机制
- 优先实现最有价值的机制（待后续讨论确定）

### Q3: 主权系统与真实 LLM 的关系？
**决策（2026-06-27）：C（实验性）**
- ✅ Trust Score 影响推理参数（temperature、top_p 等）
- ✅ 实验性探索，非生产级设计
- ✅ **已实现（2026-06-27）**：3种映射策略 + SimulatedLLM + Q3 验证代理

**实现细节**：
- `LinearMapping`：trust ∝ freedom，smooth transition
- `StepMapping`：离散跳变，按主权级别
- `ConservativeMapping`：即使高信任也保持约束
- 验证代理：`experiments/sovereignty_llm_experiment.rs`

**影响**：
- ~~需要设计 Trust Score → 推理参数的映射机制~~ ✅ 已完成
- ~~可能需要实验不同的映射策略~~ ✅ 已实现3种
- ~~需要记录实验结果，验证"真主权"的效果~~ ✅ 验证通过

**现状**：MemoryTool 使用 in-process HashMap，进程重启后丢失。

**问题**：
- 是否需要持久化内存？
  - A) 不需要（研究项目，in-process 足够）

  - C) 可选（提供 trait，用户自行实现）

### Q7: 多 Agent 拓扑的探索方向？
**现状**：当前支持 Agent 间通信，但拓扑结构未深入探索。

**问题**：
- 是否想探索特殊的 Agent 网络拓扑？

  - C) 动态拓扑（Agent 可动态加入/离开网络）
  - D) 暂不探索（先完善单 Agent 能力）
